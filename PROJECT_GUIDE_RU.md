# Шпаргалка по проекту

## 1. Кратко о проекте

Это веб-платформа для восстановления двух видов цифровых данных: повреждённых изображений и маскированных записей NetFlow. Пользователь загружает материал, запускает подходящую модель и получает результат, метаданные сессии, хэши файлов и показатели оценки. Для завершённой сессии можно скачать PDF-отчёт.

Фронтенд написан на Angular и TypeScript. Отдельный API на FastAPI отвечает за аутентификацию, загрузку файлов, запуск PyTorch-моделей, сохранение сессий и аудит действий. По умолчанию используется SQLite; конфигурацию базы можно переключить на PostgreSQL через переменную окружения.

## 2. Структура директорий

| Путь | Назначение |
| --- | --- |
| `backend/` | Python API, модели базы данных, хранение файлов, инференс и PDF-отчёты. |
| `models/` | Исходники архитектур и веса двух моделей. |
| `src/` | Angular-приложение: страницы, компоненты и сервисы. |
| `public/` | Статические ресурсы фронтенда. |
| `tests/`, `qa/` | Браузерные/интеграционные тесты и материалы проверки. |
| `.github/workflows/` | Конфигурация GitHub Actions. |
| `dist/`, `node_modules/`, `.angular/` | Результаты сборки, зависимости и кеш Angular; это не исходники приложения. |
| `db.json` | Данные для mock API (`npm run mock:api`), не основная база FastAPI. |

### `backend/`

- `app/main.py` — создаёт FastAPI-приложение, на старте инициализирует таблицы и загружает обе модели; содержит middleware аудита и endpoints состояния.
- `app/api/` — маршруты:
  - `auth.py` — регистрация и вход;
  - `uploads.py` — отдельная загрузка изображения или лог-файла;
  - `restoration.py` — восстановление, сессии и выдача результата;
  - `reports.py` — сборка PDF.
- `app/services/` — прикладная логика:
  - `image_restorer.py`, `log_restorer.py` — адаптеры инференса;
  - `models.py` — загрузка моделей один раз и их статус;
  - `files.py` — проверка, сохранение и SHA-256 файлов;
  - `audit.py` — запись событий аудита.
- `app/core/` — настройки (`config.py`) и JWT/проверка паролей (`security.py`).
- `app/db/` — SQLAlchemy-модели (`models.py`), движок и сессии БД.
- `tests/` — тесты API и smoke-тесты реальных чекпоинтов.
- `scripts/create_log_test_data.py` — создание небольших тестовых CSV из исходного NetFlow-файла.
- `storage/` и `data/` — загруженные/результирующие файлы и SQLite-БД; не исходный код.

### `models/`

- `AOT-GAN-for-paper/` — исходники модели восстановления изображений. Архитектура находится в `models/hybrid_generator.py`; вспомогательные блоки — в соседних файлах пакета.
- `GAN-for-logs/` — модель записей NetFlow и предобработка. `train_log_gan.py` содержит `RecordGenerator`, кодирование контекста и восстановление строки; `preprocess_wls.py` задаёт схему CSV.
- Активные чекпоинты, которые backend ищет в корне `models/`:
  - `hfi_gan_final.pt`;
  - `logs_best_checkpoint.pt`.
- В каталогах исходников также есть локальные checkpoint-файлы. Runtime backend использует именно два файла в корне `models/`, если `MODEL_DIR` не переопределён.

### `src/`

- `src/app/pages/` — страницы входа, dashboard и выбора моделей.
- `src/app/components/` — интерфейс загрузки/восстановления, степпер расследования, мониторинг и вспомогательные компоненты.
- `src/app/services/` — взаимодействие с API и состояние приложения.
- `src/app/app.routes.ts`, `app.config.ts` — маршрутизация и конфигурация Angular.
- `tests/` в корне проекта — Playwright-тесты; unit-тесты и e2e запускаются через npm scripts.

## 3. Ключевые файлы

### Backend

- `backend/app/main.py` — lifespan создаёт таблицы, добавляет несколько недостающих колонок в существующую SQLite-схему и вызывает `ModelRegistry.load_once()`. `GET /api/models/status` показывает готовность каждой модели. HTTP middleware пишет общий аудит запросов.
- `backend/app/services/image_restorer.py` — импортирует `HybridForensicGenerator`, загружает `hfi_gan_final.pt` со строгим сопоставлением весов, подготавливает RGB-изображение и маску, запускает forward и формирует PNG. Для эталона считает PSNR/SSIM и, если зависимости и веса есть локально, LPIPS.
- `backend/app/services/log_restorer.py` — импортирует `RecordGenerator` и функции подготовки из `train_log_gan.py`, загружает `logs_best_checkpoint.pt`, восстанавливает помеченные поля CSV и возвращает JSON-записи. При наличии эталона рассчитывает accuracy и численные ошибки.
- `backend/app/api/restoration.py` — проверяет вход и владельца файлов, создаёт сессию `processing`, вызывает нужный адаптер, сохраняет результат с SHA-256 и только после успеха ставит `completed`. Записывает события старта, успеха или ошибки в аудит.
- `backend/app/api/reports.py` — разрешает сформировать PDF только для завершённой сессии её владельца. Отчёт включает сотрудника из учётной записи, сессию, модель, время, хэши, confidence, метрики, оригинал и результат.

### Angular

- `src/app/components/gan-restoration.component.ts` — загрузка изображения, редактор маски на canvas, опциональный чистый reference, запуск image-модели и отображение результата/метрик.
- `src/app/components/log-restoration.component.ts` — отдельная форма загрузки CSV, reference и запуска модели логов.
- `src/app/components/case-workflow-stepper.component.ts` — степпер расследования: данные дела, обе независимые формы восстановления (их можно запускать независимо) и шаг скачивания PDF для завершённых сессий.
- `src/app/services/backend-api.service.ts` — HTTP-клиент для загрузки, восстановления, статуса моделей, получения результата и PDF. Базовый URL API задаётся как `http://localhost:8000/api`.
- `src/app/services/auth.service.ts` — регистрация/вход и хранение JWT в браузере.
- `src/app/services/api.interceptor.ts` — добавляет `Authorization: Bearer ...` к вызовам backend API и request ID.
- `src/app/components/monitoring-dashboard/monitoring-dashboard.component.ts` — состояние доступности API и двух моделей.

## 4. Как течёт запрос

### Изображение и маска

1. Пользователь входит в систему. Backend выдаёт JWT; Angular interceptor добавляет его к API-запросам.
2. Фронтенд отправляет файл в `POST /api/upload/image`. Backend проверяет формат и размер, сохраняет файл, SHA-256 и запись в БД.
3. Пользователь отмечает повреждённую область на canvas: белые штрихи маски означают область восстановления. Маска должна совпадать по размеру с оригиналом.
4. Фронтенд отправляет `image_id`, маску, режим `masked` и, при необходимости, чистый эталон в `POST /api/restore/image`.
5. Backend создаёт сессию `processing`; адаптер обрезает/подгоняет вход к размеру модели (обычно 256×256), запускает инференс и сохраняет PNG.
6. После сохранения результата и его SHA-256 сессия становится `completed`; ответ содержит изображение как data URL, confidence и метрики. Ошибки фиксируются как `failed` и попадают в аудит.

### NetFlow CSV

1. Фронтенд отправляет файл в `POST /api/upload/logs`; загруженный файл хэшируется и сохраняется.
2. `POST /api/restore/logs` передаёт `file_id` и необязательный эталон CSV.
3. Backend требует UTF-8 CSV с точным заголовком из 11 полей: `Time, Duration, SrcDevice, DstDevice, Protocol, SrcPort, DstPort, SrcPackets, DstPackets, SrcBytes, DstBytes`.
4. Повреждённые значения задаются как `<MASK>` или пустые поля. Модель использует контекст из пяти строк, восстанавливает маскированные поля и отдаёт JSON. Видимые значения сохраняются.
5. Успешный результат сохраняется, хэшируется и переводит сессию в `completed`; API возвращает записи, метрики и оценку confidence.

### PDF

1. После успешного восстановления степпер показывает сессию и кнопку соответствующего отчёта.
2. Angular вызывает `POST /api/report/generate` с `session_id`.
3. Backend проверяет пользователя и статус `completed`, собирает PDF из сохранённых данных и возвращает его браузеру для скачивания.

**Примечание:** поля Case identifier, Investigator и Summary сейчас находятся в интерфейсе степпера, но запрос генерации PDF отправляет только `session_id`. В отчёт попадают данные аутентифицированного сотрудника и сессии из backend, а не введённые в форму поля дела.

## 5. Ограничения моделей — важно говорить прямо

- **Изображения:** текущий `HybridForensicGenerator` принимает маску повреждений. Автоматического поиска повреждённых областей в проекте нет; `mode=auto` отклоняется. Для восстановления нужна явно нарисованная или загруженная маска.
- **Логи:** это модель для NetFlow CSV, а не произвольных текстовых логов, Windows Event Log/EVTX или JSON. Нужна точная схема из 11 колонок, на которой модель обучалась.
- **Confidence score:** у моделей нет откалиброванной вероятности правильного восстановления. Backend вычисляет эвристический показатель от 0 до 100, поэтому его нельзя называть гарантированной точностью.
  - Изображения: четыре предсказания при отражениях по горизонтали/вертикали выравниваются обратно. Формула: `100 × exp(-5 × среднее стандартное отклонение пикселей внутри маски)`.
  - NetFlow: восемь MC-dropout проходов. Для каждого восстановленного поля категории берётся максимальная усреднённая softmax-вероятность; для числа — `exp(-стандартное отклонение предсказаний в нормализованной шкале)`. Оценки полей усредняются по строкам и умножаются на 100.
- **PSNR / SSIM / LPIPS:** объективно сравнить восстановление можно только с чистым оригиналом (ground truth), который загружается отдельно как reference и не подаётся в модель. Без него эти метрики недоступны. LPIPS дополнительно требует совместимые локальные зависимости и заранее доступные веса AlexNet; backend не скачивает их автоматически.
- Для логов reference должен иметь ту же схему, количество строк и порядок; сравнение выполняется по восстановленным маскированным значениям. Accuracy — exact match для категорий, MAE/RMSE — отдельно для каждого числового поля.
- Backend запускает инференс на CUDA, если PyTorch видит GPU, иначе на CPU. Время выполнения на CPU может быть заметным.

## 6. Как запустить

Нужны Python, Node.js/npm и установленные зависимости моделей/backend. В PowerShell из корня проекта:

### Backend

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
python -m pip install -r requirements-dev.txt
uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

Для уже настроенного окружения достаточно активировать `.venv` и выполнить команду `uvicorn`. Параметры подключения описаны в `backend/.env.example`: `DATABASE_URL`, `STORAGE_DIR`, `MODEL_DIR`, `JWT_SECRET`, `ACCESS_TOKEN_MINUTES`, `MAX_UPLOAD_BYTES`, `CORS_ORIGINS`. Не меняйте `JWT_SECRET` между перезапусками, если нужны действующие токены.

### Frontend

В отдельном терминале из корня:

```powershell
npm install
npm start
```

Откройте `http://localhost:4200/gan-models`, зарегистрируйтесь или войдите. Для работы интерфейса backend должен быть доступен на `http://localhost:8000`.

### Проверка

- API health: `http://127.0.0.1:8000/api/health` (дополнительно доступен `/health`).
- Документация FastAPI: `http://127.0.0.1:8000/docs`.
- Статус чекпоинтов: `http://127.0.0.1:8000/api/models/status`. Для `image` и `logs` ожидаются `checkpoint_loaded: true` и `inference_ready: true`.
- Тесты backend: из папки `backend` — `.\.venv\Scripts\python.exe -m pytest tests -q`.
- Сборки фронтенда: из корня — `npm run build` и `npm run build:ssr`.

## 7. Короткие ответы научному руководителю

**«Покажи, где подключается модель»**  
«На старте FastAPI `backend/app/main.py` вызывает `ModelRegistry.load_once()` из `backend/app/services/models.py`. Модель изображений инициализирует `backend/app/services/image_restorer.py`, модель NetFlow — `backend/app/services/log_restorer.py`. Архитектуры и чекпоинты лежат в `models/AOT-GAN-for-paper/` и `models/GAN-for-logs/`; активные веса — `models/hfi_gan_final.pt` и `models/logs_best_checkpoint.pt`. Состояние загрузки видно через `/api/models/status`».

**«Какой стек и архитектура?»**  
«Angular/TypeScript — пользовательский интерфейс; FastAPI — REST API и аутентификация JWT; PyTorch — две независимые модели инференса; SQLAlchemy и SQLite по умолчанию — пользователи, файлы, сессии и аудит; ReportLab — PDF. Фронтенд загружает файл и вызывает API, backend сохраняет доказательные данные и вызывает соответствующий адаптер».

**«Откуда берётся процент уверенности?»**  
«Это не точность, измеренная на эталоне, и не калиброванная вероятность. Для изображений score основан на согласованности четырёх предсказаний при отражениях. Для NetFlow — на восьми MC-dropout проходах, вероятности категорий и разбросе числовых предсказаний. Реальное качество оценивается отдельно по чистому reference».

**«Почему модель логов не работает с обычными логами?»**  
«Она обучена на фиксированной схеме NetFlow из 11 полей, а её кодирование, словари категорий и нормализация чисел привязаны к этому формату. Обычный текстовый лог или Windows EVTX не содержит нужной структуры и не может быть корректно подан этой модели без отдельного парсера и переобучения/адаптации».
