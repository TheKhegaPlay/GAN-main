--- DynamicFormService (form builder & validators mapping) ---
File: src/app/dynamic-forms/dynamic-form.service.ts

Purpose: Converts metadata (FieldConfig array) into a reactive FormGroup with properly mapped validators and default values.

Key code quote 1 - buildGroup method (form creation):
  buildGroup(fields: FieldConfig[]) {
    const group: Record<string, any> = {};
    for (const f of fields) {
      const validators = this.mapValidators(f.validators || []);
      let defaultValue: any = null;
      if (f.type === 'multiselect' || f.type === 'multiselect-search') defaultValue = [];
      if (f.type === 'checkbox') defaultValue = false;
      group[f.name] = [{ value: defaultValue, disabled: !!f.disabled }, validators];
    }
    return this.fb.group(group);
  }
Explanation: Iterates over FieldConfig array, sets appropriate default values (multiselect/multiselect-search -> [], checkbox -> false, otherwise -> null), applies validators, and builds a FormGroup. The second parameter in the array is the validators list.

Key code quote 2 - mapValidators method (required validator):
  case 'required':
    arr.push(Validators.required);
    break;
Explanation: Maps the 'required' validator name to Angular's built-in Validators.required function.

Key code quote 3 - mapValidators method (min/max validators):
  case 'min':
    arr.push(Validators.min(c.args));
    break;
  case 'max':
    arr.push(Validators.max(c.args));
    break;
Explanation: Maps 'min' and 'max' validators with their numeric arguments (e.g., { name: 'min', args: 0 }).

Key code quote 4 - mapValidators method (pattern validator):
  case 'pattern':
    arr.push(Validators.pattern(c.args));
    break;
Explanation: Maps 'pattern' validator with regex pattern as argument (e.g., { name: 'pattern', args: /^[A-Z]+$/ }).

Key code quote 5 - mapValidators method (email validator):

Key code quote 6 - mapValidators method (phone validator with international format):

    const c = this.form.controls[name];
    return !!(c && c.invalid && (c.touched || c.dirty));
  }
Explanation: The "invalid" CSS class is applied when the control is invalid AND (touched OR dirty). The method checks both states to provide appropriate UX feedback.

Key code quote 5 - Multiselect change handler:
  onMultiSelectChange(fieldName: string, event: Event): void {
    const control = this.form.get(fieldName);
    const selectedOptions = control.value || [];
    const value = (event.target as HTMLInputElement).value;
    if ((event.target as HTMLInputElement).checked) {
      control.setValue([...selectedOptions, value]);
    } else {
      control.setValue(selectedOptions.filter((v: any) => v !== value));
    }
    control.markAsDirty();
    control.markAsTouched();
  }
Explanation: When a checkbox in a multiselect field is toggled, this method adds/removes the value from the control's array, marks the control as dirty and touched for validation display.

Key code quote 6 - Searchable multiselect filter:
  onSearchChange(fieldName: string, query: string): void {
    this.searchQueries[fieldName] = query?.toLowerCase() || '';
  }

  getFilteredOptions(f: FieldConfig) {
    const q = (this.searchQueries[f.name] || '').trim();
    if (!f.options) return [];
    if (!q) return f.options;
    return f.options.filter(o => String(o.label).toLowerCase().includes(q) || String(o.value).toLowerCase().includes(q));
  }
Explanation: onSearchChange stores the search query; getFilteredOptions filters options by matching both label and value against the query string (case-insensitive).

Key code quote 7 - Form submission (mark all as touched if invalid):
  submit() {
    if (this.form.valid) {
      console.log('Dynamic form submit', this.form.value);
      alert('Форма успешно отправлена (см. консоль)');
    } else {
      Object.values(this.form.controls).forEach((ctrl) => (ctrl as AbstractControl).markAsTouched());
    }
  }
Explanation: If the form is valid, logs the data. If invalid, marks all controls as touched to reveal validation errors to the user.

4. How CVA and validation are integrated
- StarRatingComponent implements the full CVA contract (writeValue, registerOnChange, registerOnTouched, setDisabledState) and the Validator interface (validate method).
- When a user selects a star, setValue() calls onChange() to notify the parent form and onTouched() to update the touched state.
- DynamicFormService maps FieldConfig validators to Angular Validators and attaches them to FormControls.
- DynamicFormComponent displays error messages when control.invalid && (touched || dirty), providing visual feedback via CSS and text.
- All controls in the dynamic form are part of a single FormGroup, allowing the form to enforce required validators and prevent submission until all required fields are valid.

5. How the rating field works in the dynamic form
- The rating field uses native radio inputs (not the CVA component) in the dynamic renderer for reliability and browser compatibility.
- Each radio input is bound via [formControlName]="f.name" to the corresponding FormControl.
- When a user clicks a star (radio), the form control's value updates to the numeric rating (1-5).
- If the required validator is applied and no star is selected, the control is invalid.
- On submit, if invalid, the component marks all controls as touched to reveal errors.

6. Notes and recommendations
- Reusability: StarRatingComponent is standalone and fully reusable. To use it in the dynamic renderer, replace the radio template with:
  <app-star-rating [formControlName]="f.name" [required]="hasRequired(f)" [maxStars]="5"></app-star-rating>
- Extensibility: DynamicFormService currently supports flat structures. For nested forms (FormGroup/FormArray), extend FieldConfig with a children property and implement recursive group building.
- Validation: Custom validators can be added to mapValidators(). For example, implement a 'minDate' validator by adding a case for it and using Validators.minDate().
- UX improvement: Consider adding async validators (e.g., checking username availability) by supporting AsyncValidatorFn in ValidatorConfig.
